# Optional OCR engine extras. Install with:
#   pip install -r requirements-paddleocr.txt
#
# This installs PaddleOCR (PP-OCRv4) plus paddlepaddle. ~250 MB of pip deps
# plus ~18 MB of model files downloaded on first use (PP-OCRv4 ch model).
#
# Why optional: Tesseract is the default engine and works without these
# heavy deps. Only install PaddleOCR if you need its better recall on
# Chinese power-drawing PDFs.
#
# Use it via:  python scripts/cable_match.py --engine paddleocr ...
#
# === Version pinning notes (validated on macOS Py3.12 + Win/Linux Py3.10+) ===
# PaddleOCR 2.7.3 is the last version with the simple lang=ch model API.
# Newer 3.x versions require matching paddlex 3.x which needs paddlepaddle
# 3.2+; the paddlepaddle 3.2+ macOS wheel is currently broken (paddlex ABI
# mismatch at init). The 2.7.3 + 2.6.2 stack below is the most-recent
# STABLE COMBINATION that works on macOS without C++ compilation.
#
# On Win/Linux, paddlepaddle 3.0+ and paddleocr 3.0+ work fine if you
# want newer features. For pure cable matching, PP-OCRv4 in 2.7.3 is
# already good enough.
#
# Test fixture: D0202-04/33/67 (3 PDFs, Mac CPU):
#   Tesseract:    13 unique cables
#   PaddleOCR:    11 unique cables
#   Union:        18 unique cables (+38-64% recall vs single engine)
#   Paddle missed 1F-151/GPS-1F/GPST-1F (lang=ch drops Latin); Tesseract
#   missed 3B-437/3B-503/3B-508/5071-142. **The 2 engines are complementary.**
#
# macOS Apple Silicon note: paddlepaddle 2.6.2 has no GPU wheel for M-series;
# use `--use_gpu` flag only on Linux/Windows with CUDA. CPU mode on Mac is
# ~50-100ms/page, ~2-3x slower than Tesseract CPU. Win11 GPU ~5-10ms/page.
#
# === NumPy 1.x ABI pinning (CRITICAL for paddlepaddle 2.6.2) ===
# paddlepaddle 2.6.2 / paddleocr 2.7.3 ship C extensions compiled against
# NumPy 1.x ABI (0x1000009). NumPy 2.0 changed the C ABI's major version
# (now 0x2000000) so these .pyd/.so files refuse to load:
#     ImportError: numpy.core.multiarray failed to import
#     RuntimeError: module compiled against ABI version 0x1000009 but
#                   this version of numpy is 0x2000000
#
# When you `pip install -r requirements-paddleocr.txt` without pins, pip
# resolver may pick the LATEST versions of transitive deps (scipy 1.18+,
# scikit-image 0.25+, matplotlib 3.10+, Pillow 12+, shapely 2.1+, etc.)
# which ALL hard-require numpy>=2.0. That contradicts paddlepaddle 2.6.2's
# numpy<2.0 requirement, and pip will silently install numpy 2.x and
# paddlepaddle will fail to load at runtime.
#
# The pins below block those numpy-2-only versions so pip keeps numpy 1.26.x.
# If you want to upgrade to paddleocr 3.x + paddlepaddle 3.x, you can
# remove these pins (the 3.x stack is numpy-2 compatible by design).

numpy<2.0                  # paddlepaddle 2.x ABI compat (MUST be first)
scipy<1.15                 # 1.15+ hard-requires numpy>=2.0
scikit-image<0.25          # 0.25+ hard-requires numpy>=2.0
matplotlib<3.10            # 3.10+ hard-requires numpy>=2.0
shapely<2.1                # 2.1+ hard-requires numpy>=2.0
Pillow<11                  # 12+ hard-requires numpy>=2.0
pdf2docx<0.5.10            # 0.5.10+ requires Py3.10+ AND pulls scipy 1.15+
imgaug==0.4.0              # only this release; pulls scipy but is OK with <1.15

paddleocr==2.7.3
paddlepaddle==2.6.2
